# 记忆系统

目标：让它像人一样记事——重要的事记很久，琐碎的事慢慢淡忘，常常聊到的事越记越牢；
在群里，每个人都有自己的那份记忆。

实现：`server/memory.mjs`（约 700 行，零依赖）。

---

## 一、分层

```
scopes/<talker>.json
├── chat[]                    会话级记忆（这个聊天里发生的事）
└── members{}
    └── <wxid>
        ├── memories[]        成员专属记忆（这个人的身份/偏好/性格）
        └── profile           由记忆汇总的人物画像
```

私聊里，对方也是一个"成员"，所以同样有专属记忆和画像——
这样同一个人以后出现在群里，记忆能直接用上。

## 二、一条记忆长什么样

```json
{
  "id": "uuid",
  "kind": "fact | preference | event | profile | relation",
  "text": "对芒果过敏，需避免含芒果的食物",
  "tags": ["健康", "过敏"],
  "importance": 0.9,
  "label": "非常重要",
  "createdAt": 1793530000000,
  "lastAccessAt": 1793530000000,
  "accessCount": 2,
  "pinned": false,
  "source": "auto | manual | tool | compressed",
  "memberName": "泽哥"
}
```

## 三、写入：自动打标签

每轮回复发出后（异步），用模型给这轮对话打分并抽记忆：

```json
{
  "importance": 0.9,
  "label": "非常重要",
  "tags": ["健康", "过敏"],
  "items": [
    { "kind": "preference", "text": "对芒果过敏", "importance": 0.9, "tags": ["健康"] }
  ]
}
```

规则（写在提示词里）：

- 只记用户透露的信息，**不记**机器人自己说的话
- 不记「用户问了一个问题」这类交互事实
- 每条 ≤ 40 字，陈述句，第三人称
- 重要度低于 `tag.minImportance`（0.12）直接丢弃
- 每轮最多 `tag.maxItemsPerTurn`（4）条

分流规则：

| 内容 | 去哪 |
|---|---|
| 关于"这个人"（身份 / 偏好 / 性格 / 关系） | 成员记忆 |
| 关于"这个聊天里发生的事"（`kind=event`） | 会话记忆 |

去重：

- 同桶内相似度 > 0.82 → 合并（重要度取高、复习次数 +1、标签并集）
- **跨桶也查一遍**：同一个事实不会既在会话记忆又在成员记忆里各存一份

## 四、遗忘：艾宾浩斯曲线

```
留存率  R = e^(-Δt / S)
稳定性  S = baseStabilityHours × e^(importance × importanceExp)
                              × (1 + ln(1 + accessCount) × accessBoost)

默认：baseStabilityHours = 26，importanceExp = 4.6，accessBoost = 0.55
```

`Δt` 是「距上次被想起」的小时数。

| importance | S（小时） | 3 天 | 7 天 | 30 天 | 90 天 | 行为 |
|---|---|---|---|---|---|---|
| 0.10 | ~41 | 17% | 1% | 0% | 0% | 约 1.5 天遗忘 |
| 0.30 | ~102 | 49% | 18% | 0% | 0% | 约 4 天遗忘 |
| 0.50 | ~259 | 76% | 53% | 6% | 0% | 约 2 周遗忘 |
| 0.75 | ~777 | 91% | 81% | 40% | 1% | 约 1 个月遗忘 |
| 0.90 | ~1630 | 96% | 90% | 64% | 27% | 90 天仍 27%，且被钉住 |

处理规则：

- `R < forgetThreshold`（0.26）→ **归档**（`archiveInsteadOfDelete: true`，可捞回）
- `importance ≥ pinImportance`（0.85）或 `pinned: true` → **永不自动遗忘**
- 巡检周期 `sweepIntervalMinutes`（默认 30 分钟），也可在后台手动「预演 / 执行」

### 复习效应

检索命中时会 `touch`：

- `lastAccessAt = now`（计时器归零）
- `accessCount += 1`（稳定性 ×(1+ln(1+n)×0.55)，第二次命中约 +38%）
- `importance += 0.03`（上限 1）

所以"天天聊到的事"会越来越难忘，这跟人类的间隔重复效应一致。

## 五、检索：该想起什么

调用模型前，对候选记忆打分：

```
score = 关键词命中 × 0.45
      + 留存率   × 0.25
      + 重要度   × 0.20
      + 新近度   × 0.10        // 1 / (1 + 年龄小时/72)
      + 同人加成 × 0.12        // 说话人自己的记忆优先
```

- 关键词命中用**中文字符二元组**（bigram）+ 英文单词，`命中数 / 查询词数`
- 低于 `retrieve.minScore`（0.18）丢弃，最多取会话 8 条 + 成员 6 条
- 命中的会被"复习"（见上）

注入格式：

```
【你记得关于聊天对象的事】
- 小明：喜欢打羽毛球（爱好/运动）
【这个聊天里你记得的事】
- 群里约了周六去爬山（约定）
以上是你凭记忆想起的旧事。自然地运用它们（别生硬复述），如果和当前话题无关就忽略。
```

## 六、压缩：记忆太多怎么办

触发条件：会话记忆数 > `maxChatMemories`（120），或成员记忆总数超额。

策略：

1. 挑选「未钉住 + importance < 0.7 + 最久没被想起」的一批
2. 按 `kind` 聚簇
3. 让模型把每簇合成一句 ≤ 80 字摘要（失败则朴素拼接）
4. 生成一条 `source: "compressed"` 的记忆，重要度略高于原簇最高值，`mergedFrom` 记录条数
5. 删除原始条目

**重要记忆（≥0.85）不参与压缩**，细节优先保住。

## 七、画像

成员记忆每积累 `profile.everyN`（10）条，自动重建一次画像：

```
人物：小明
记忆：
- 是程序员
- 喜欢打羽毛球
- 说话很直
→ 画像：「说话直来直去，程序员，爱运动，跟我是老同学，聊技术话题会兴奋。」
```

也可以在后台手动「重建画像」。

## 八、后台管理

控制台「记忆」页：

- 左：有记忆的会话（会话数 / 成员数 / 即将遗忘数）
- 中：会话记忆 / 群成员 / 归档 三个 tab，每张卡显示标签、重要度、**记忆强度进度条**、存在时长、上次回忆
- 右：上下文用量条 + 手动新增 + 选中成员的画像
- 操作：钉住、编辑、忘掉、搜索、压缩记忆、预演/执行遗忘、全库巡检、从归档捞回

## 九、调参建议

| 想要的效果 | 调什么 |
|---|---|
| 忘得更快（更"健忘"） | 调低 `decay.baseStabilityHours` 或调高 `forgetThreshold` |
| 让"重要"更值钱 | 调高 `decay.importanceExp` |
| 少存点垃圾 | 调高 `tag.minImportance`、降低 `tag.maxItemsPerTurn` |
| 省钱（少一次模型调用） | `memory.autoTag = false`，只用模型主动 `remember` |
| 记忆库别太大 | 调低 `maxChatMemories` / `maxMemberMemories` |

所有参数在 `config.json` 的 `memory` 段，也可以在单个聊天的 `chats[talker].memory` 里覆盖。
